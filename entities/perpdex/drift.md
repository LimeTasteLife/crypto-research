# Drift

> An open-source decentralized perpetuals exchange on Solana with a three-layer matching engine (JIT auctions → Decentralized Limit Order Book (DLOB) → backstop virtual AMM), cross-margined risk engine across spot+perp, an in-house multi-asset Insurance Fund hierarchy backed by DRIFT-staked Drift Safety Module, and three first-class market-maker entry points (DLOB, JIT-only, SWIFT signed-message API).

## Snapshot
- Market structure: hybrid CLOB + vAMM — JIT Dutch auctions feed a Decentralized Limit Orderbook (DLOB) which is backstopped by a constant-product virtual AMM with dynamic spread/peg[^drift-docs-2026-04-28-protocol-about-v3][^drift-docs-2026-04-28-protocol-about-v3-matching-engine][^drift-developers-docs-2026-04-28-developers-market-makers-orderbook-and-matching]
- Operator: Drift Labs (Solana program author + bot operator) and the DRIFT DAO (parameter governance + Safety-Module incentives)[^drift-docs-2026-04-28-protocol-risk-and-safety-drift-safety-module][^drift-developers-docs-2026-04-28-developers-concepts-account-model]
- Native token: [[entities/token/drift]] (fee-discount staking tiers, Drift Safety Module backstop, governance)[^drift-docs-2026-04-28-protocol-trading-trading-fees][^drift-docs-2026-04-28-protocol-risk-and-safety-drift-safety-module]
- Network: [[entities/network/solana]] (single-chain venue; Solana program implementation)[^drift-docs-2026-04-28-index][^drift-developers-docs-2026-04-28-developers-concepts-account-model]
- Product surface: Perpetuals, Spot Trading, Borrow & Lend, Token Swaps, Passive Liquidity Provision via Backstop AMM Liquidity (BAL) and Insurance Fund Staking[^drift-docs-2026-04-28-protocol-about-v3][^drift-docs-2026-04-28-index]
- App entry points: app.drift.trade UI; first-party SDKs in TypeScript (`@drift-labs/sdk`), Python (`driftpy`), and Rust (`drift-rs`); a self-hosted Drift Gateway HTTP API; a hosted Data API for analytics[^drift-developers-docs-2026-04-28-developers][^drift-docs-2026-04-28-index]

## Mechanism

**Three-layer matching: JIT → DLOB → AMM.** Drift is described as a decentralized auction-based matching protocol[^drift-docs-2026-04-28-protocol-about-v3-matching-engine]. Every market taker order carries five auction parameters — auction duration in slots, auction start price, auction end price, post-auction limit price, and max timestamp — defining a linear price function over slots[^drift-docs-2026-04-28-protocol-about-v3-matching-engine]. Auction prices can be fixed or relative oracle offsets to track oracle moves during the auction[^drift-docs-2026-04-28-protocol-about-v3-matching-engine]. Market orders REQUIRE auction + max timestamp; limit orders may have them[^drift-docs-2026-04-28-protocol-about-v3-matching-engine]. Liquidity matching priority on a taker arrival: (1) JIT Auction (typically 10 slots ≈ 5s) where MMs compete to fill at better prices; (2) DLOB resting orders matched by price-time priority; (3) Backstop AMM as last-resort fill[^drift-developers-docs-2026-04-28-developers-market-makers-orderbook-and-matching][^drift-developers-docs-2026-04-28-developers-market-makers-jit-auctions]. CRITICALLY: backstop AMM liquidity is compared against resting and JIT liquidity before each fill — if backstop offers a superior price, Drift fills against backstop first[^drift-docs-2026-04-28-protocol-about-v3-matching-engine]. For spot, the matching engine can also route through external venues (Phoenix, OpenBook, Jupiter aggregator) when they offer better prices[^drift-developers-docs-2026-04-28-developers-market-makers-orderbook-and-matching].

**JIT auction details.** A JIT auction is a reverse Dutch auction: starts at the taker's best price and deteriorates toward their worst acceptable price, interpolated as `Auction Price(slot) = start + (end − start) × min(1, (current − start_slot) / duration)`[^drift-developers-docs-2026-04-28-developers-market-makers-jit-auctions]. Auction slots are Solana slots (~400ms wall-clock), so network congestion stretches the auction window[^drift-developers-docs-2026-04-28-developers-market-makers-jit-auctions]. Multiple makers can fill the same taker order; better prices get pro-rata best-price priority[^drift-developers-docs-2026-04-28-developers-market-makers-jit-auctions]. After the auction expires, unfilled taker size matches against DLOB then AMM[^drift-developers-docs-2026-04-28-developers-market-makers-jit-auctions]. Limit orders that don't cross the spread bypass the auction entirely[^drift-developers-docs-2026-04-28-developers-market-makers-jit-auctions]. JIT auctions typically add 5–10 slot delay (~2–5 seconds) before taker execution but provide better prices[^drift-developers-docs-2026-04-28-developers-market-makers-jit-auctions]. JIT makers see retail flow ~5 seconds before it hits the market[^drift-docs-2026-04-28-protocol-market-makers-market-maker-participation].

**Decentralized orderbook (DLOB).** The DLOB aggregates resting limit orders across all UserAccounts; storing a sorted orderbook onchain would be prohibitively expensive on Solana, so Drift stores orders in user accounts and the DLOB sorts them offchain[^drift-developers-docs-2026-04-28-developers-market-makers-orderbook-and-matching]. A permissionless network of Keeper Bots matches open orders against on-chain liquidity sources when triggers are met; each Keeper maintains its own independent view[^drift-docs-2026-04-28-protocol-about-v3-decentralized-orderbook][^drift-docs-2026-04-28-protocol-about-v3]. Keepers earn rewards for providing best execution relative to oracle and for following First-Come-First-Serve ordering; existing JIT maker bots and resting-order taker bots implicitly fulfill the keeper role[^drift-docs-2026-04-28-protocol-about-v3-decentralized-orderbook]. The DLOB never modifies onchain state — it is read-only, and if it goes down, orders remain valid onchain (just temporarily not visible in the aggregated book)[^drift-developers-docs-2026-04-28-developers-market-makers-orderbook-and-matching]. The protocol's core functionality does NOT depend on the keeper network — keepers improve throughput/usability but are not load-bearing[^drift-docs-2026-04-28-protocol-about-v3-decentralized-orderbook]. Three post-only modes are exposed: MUST_POST_ONLY (rejects if would cross), TRY_POST_ONLY (amends to non-crossing), SLIDE (slides to best bid/ask)[^drift-developers-docs-2026-04-28-developers-market-makers-dlob-mm]. Two post-only maker orders cannot be crossed against each other[^drift-docs-2026-04-28-protocol-about-v3-decentralized-orderbook]. Maker orders that fill against the AMM are NOT eligible for rebate reward — a notable carve-out[^drift-docs-2026-04-28-protocol-about-v3-decentralized-orderbook].

**Backstop virtual AMM.** Drift's v3 vAMM is constant-product (`x*y=k`) augmented with three runtime knobs: external Backstop AMM Liquidity (BAL), a concentration factor, and dynamic spread/peg programmatically updated prior to filling[^drift-docs-2026-04-28-protocol-about-v3-drift-amm][^drift-docs-2026-04-28-protocol-about-v3]. The vAMM has an inbuilt bid-ask spread that adjusts based on inventory held and quotes asymmetrically (different prices for buys vs sells)[^drift-docs-2026-04-28-protocol-about-v3][^drift-docs-2026-04-28-protocol-about-v3-drift-amm]. Bid/ask = reservation_price ± base_spread + f(inventory, balance, …)[^drift-docs-2026-04-28-protocol-about-v3-drift-amm]. The ask − bid never exceeds a max spread expressed as a percentage of the current valid oracle price[^drift-docs-2026-04-28-protocol-about-v3-drift-amm]. The AMM moves its peg toward the oracle price each fill cycle and is updated in the same slot with a valid oracle price every time a trader fills against it[^drift-docs-2026-04-28-protocol-about-v3-drift-amm]. Orders fill against the AMM only after the order has lived longer than the minimum AMM-fill duration of 10 slots[^drift-docs-2026-04-28-protocol-about-v3-drift-amm]. Effective leverage of the AMM (a function of inventory PnL and fee-pool collateral) widens the spread when the AMM is heavily levered or in debt[^drift-docs-2026-04-28-protocol-about-v3-drift-amm]. The AMM allows Drift to bootstrap new markets without external market makers, with the caveat that unsettled PnL availability adds risk[^drift-docs-2026-04-28-protocol-about-v3].

**Three market-maker strategies (DLOB, JIT-only, SWIFT).** Drift documents three first-class MM entry points[^drift-developers-docs-2026-04-28-developers-market-makers]. (1) **DLOB MM** — resting two-sided post-only quotes on the DLOB; capital locked onchain; lower latency requirements; oracle offset orders strongly recommended (set `orderType: ORACLE` with `oraclePriceOffset` so the order auto-tracks oracle at fill — typical MM sends ~30 transactions per day vs thousands with cancel-replace)[^drift-developers-docs-2026-04-28-developers-market-makers-dlob-mm]. (2) **JIT-only MM** — react to taker auctions in real-time during JIT; capital deployed only on fill; selective flow inspection; reduces adverse selection from stale quotes; requires lower-latency infrastructure[^drift-developers-docs-2026-04-28-developers-market-makers-jit-only][^drift-developers-docs-2026-04-28-developers-market-makers]. (3) **SWIFT API** — receive signed taker orders offchain via WebSocket BEFORE they hit the JIT auction; 100–500ms head-start over the standard 1–2s onchain auction visibility; uses `placeAndMakeSignedMsgPerpOrder` with ed25519 verification (must be the FIRST instruction in the transaction or silent verification fails); SWIFT is not guaranteed flow — not all takers route through it[^drift-developers-docs-2026-04-28-developers-market-makers-swift-api][^drift-developers-docs-2026-04-28-developers-drift-sdk-swift]. All three strategies earn the same maker rebates with no additional SWIFT-specific fees[^drift-developers-docs-2026-04-28-developers-market-makers-swift-api]. Drift open-sources reference bots in keeper-bots-v2: FloatingPerpMaker (oracle-offset DLOB) and JitMaker (JIT fills via JitterSniper / JitterShotgun from `@drift-labs/jit-proxy`); critically, Drift itself runs the floating maker bot on-platform for-profit with additional risk parameters — explicit protocol-as-MM disclosure[^drift-docs-2026-04-28-protocol-market-makers-market-maker-participation][^drift-developers-docs-2026-04-28-developers-market-makers].

**Indicative quotes.** A separate offchain-only signaling layer (`wss://dlob.drift.trade/quotes/ws`, challenge-response auth with the MM keypair) lets MMs publish bid/ask quotes that appear in the L2 orderbook only when `includeIndicative=true`; quotes are NOT firm commitments (no onchain enforcement); used for UI display, aggregator routing, and JIT-only MM visibility[^drift-developers-docs-2026-04-28-developers-market-makers-indicative-quotes].

**Account model and Solana program.** The Drift program manages five account types[^drift-developers-docs-2026-04-28-developers-concepts-account-model]. **State** (singleton) holds protocol-wide config: oracle guards, perp+spot fee structures, sequencer settings, admin controls, emergency flags. **PerpMarketAccount** (one per market) stores AMM state, funding rates, oracle integration, marginRatioInitial, marginRatioMaintenance, imfFactor, liquidatorFee, ifLiquidationFee, contractTier, marketStatus. **SpotMarketAccount** (one per spot market) stores oracle, vault, insurance fund, deposit/borrow balances, asset/liability weights, optimalUtilization/optimalBorrowRate/maxBorrowRate. **UserAccount** (per subaccount) stores up to 32 active orders, perp + spot positions, margin settings, delegate addresses[^drift-developers-docs-2026-04-28-developers-concepts-account-model][^drift-docs-2026-04-28-protocol-risk-and-safety-risk-parameters]. **UserStatsAccount** (per wallet) tracks lifetime fee, 30-day maker/taker/filler volume, referrer info, fuel points[^drift-developers-docs-2026-04-28-developers-concepts-account-model]. Each wallet can have up to 1000 sub-accounts sharing cross-margin via UserStats (the SDK overview notes 1000 subaccount cap, account-model page emphasises 32 orders per subaccount — multi-market MM is recommended to use 1:1 subaccount-to-market mapping)[^drift-sdk-docs-2026-04-28-concepts-overview][^drift-developers-docs-2026-04-28-developers-concepts-account-model][^drift-developers-docs-2026-04-28-developers-market-makers-dlob-mm]. ExchangeStatus is a bitflag with values ACTIVE=0, DEPOSIT_PAUSED=1, WITHDRAW_PAUSED=2, AMM_PAUSED=4, FILL_PAUSED=8, LIQ_PAUSED=16, FUNDING_PAUSED=32, SETTLE_PNL_PAUSED=64, AMM_IMMEDIATE_FILL_PAUSED=128, PAUSED=255 — granular admin pause surface[^drift-sdk-docs-2026-04-28-concepts-overview]. MarketStatus enum: INITIALIZED, ACTIVE, FUNDING_PAUSED, AMM_PAUSED, FILL_PAUSED, WITHDRAW_PAUSED, REDUCE_ONLY, SETTLEMENT, DELISTED[^drift-sdk-docs-2026-04-28-concepts-overview].

**Cross-margin and isolated margin.** Cross-margin is the default; all deposits act as collateral for all positions, and unrealized PnL contributes to margin (with haircuts via `pnlAssetWeight`)[^drift-sdk-docs-2026-04-28-concepts-margin][^drift-developers-docs-2026-04-28-developers-concepts]. Total Collateral = Σ(token deposit × price × asset weight) + Σ(positive perp PnL × pnlAssetWeight); Margin Requirement = Σ(perp position notional × marginRatio) + Σ(borrow × liabilityWeight)[^drift-sdk-docs-2026-04-28-concepts-margin]. An account is liquidatable when totalCollateral < marginRequirement(maintenance)[^drift-sdk-docs-2026-04-28-concepts-margin]. Isolated margin is gated to ISOLATED-tier markets only and was introduced in v2.154.0 — only one isolated position per market, cannot mix with cross-margin in the same market, liquidated independently[^drift-sdk-docs-2026-04-28-concepts-positions][^drift-sdk-docs-2026-04-28-concepts-margin]. MarginMode enum: DEFAULT (cross), HIGH_LEVERAGE (lower IM/MM, may be reduce-only and capped by `maxUsers`), HIGH_LEVERAGE_MAINTENANCE[^drift-sdk-docs-2026-04-28-concepts-margin]. Size-based scaling via IMF: `marginRatio = baseMarginRatio + imfFactor × sqrt(size × 10)`; spot asset-weight discount: `assetWeight_eff = (1.1 × assetWeight) / (1 + imfFactor × sqrt(size × 10))`[^drift-sdk-docs-2026-04-28-concepts-margin][^drift-docs-2026-04-28-protocol-risk-and-safety-risk-parameters]. Strict oracle prices for spot margin: assets use `oracle − confidence`, liabilities use `oracle + confidence`[^drift-sdk-docs-2026-04-28-concepts-margin].

**Contract Tiers and Asset Tiers.** Drift defines six Contract Tier labels (A, B, C, Speculative, Highly Speculative, Isolated — the docs call them "five unique tiers" while listing six labels)[^drift-docs-2026-04-28-protocol-trading-market-specs][^drift-sdk-docs-2026-04-28-concepts-overview]. Tiers govern priority access to collateral in liquidations, max insurance limits, acceptable oracle price divergence, and TWAP / funding-rate sanitization[^drift-docs-2026-04-28-protocol-trading-market-specs]. As of snapshot: BTC-PERP is Tier A; SOL-PERP and ETH-PERP are Tier B; 1MBONK-PERP, 1MPEPE-PERP, WIF-PERP are Speculative; W-PERP is Highly Speculative; most others are Tier C[^drift-docs-2026-04-28-protocol-trading-market-specs]. Speculative tier markets have NO access to external insurance funds — only the perpetual market's own fee pool[^drift-docs-2026-04-28-protocol-trading-market-specs]. Highly Speculative sits one tranche below. Isolated tier requires the user to disable cross-margin trading on both perpetual and spot; users with margin trading enabled, a non-USDC borrow, or another perp position cannot enter[^drift-docs-2026-04-28-protocol-trading-market-specs]. Spot Asset Tiers: Collateral (full privilege), Protected (collateral, no borrow), Cross (not collateral, allow multi-borrow), Isolated (not collateral, single borrow), Unlisted (no privilege)[^drift-docs-2026-04-28-protocol-trading-market-specs]. Each perp market exposes Max Open Interest, IMF Factor, and Oracle Source (Pyth | Switchboard | Prelaunch) parameters[^drift-docs-2026-04-28-protocol-trading-market-specs].

**Oracle integrity guards.** Each Drift market tracks last-seen oracle values and updates an EMA TWAP over both 1hr (funding period) and 5min intervals[^drift-docs-2026-04-28-protocol-trading-oracles]. Drift uses Pyth by default and can support other sources per market (Switchboard for production, plus a custom internal "Prelaunch" oracle that uses mark TWAP as the price for markets without an external spot reference)[^drift-docs-2026-04-28-protocol-about-v3][^drift-docs-2026-04-28-protocol-trading-market-specs]. The protocol runs four validity guard checks per oracle update: **Stale-for-AMM** (>10 slots behind current slot); **Stale-for-Margin** (>120 slots behind); **InvalidPrice** (any negative price field); **TooVolatile** (TWAP/price ratio out of [0.2, 5]); **TooUncertain** (confidence > 10% of price)[^drift-docs-2026-04-28-protocol-trading-oracles]. When invalid, the perpetual market may block fills, withdraws, liquidations, and funding-rate updates that would increase protocol risk[^drift-docs-2026-04-28-protocol-trading-oracles]. During the invalid period, the on-chain oracle TWAP shrinks toward mark TWAP to prevent erroneous funding magnitudes[^drift-docs-2026-04-28-protocol-trading-oracles]. The MM-oriented `getMMOracleDataForPerpMarket` accessor returns MM-specific data including a validity flag and confidence interval; bots are instructed to skip fills when `oracle.isValid` is false[^drift-developers-docs-2026-04-28-developers-market-makers-jit-only].

**Mark price and 10% price-band guard.** Mark price updates each oracle update and each contract interaction; reservation (AMM) price = `quote_reserves / base_reserves * peg`[^drift-docs-2026-04-28-protocol-about-v3-drift-amm]. Drift v3 prevents users from sending orders if oracle-mark divergence breaches a 10% band relative to the oracle's 5-minute TWAP[^drift-docs-2026-04-28-protocol-risk-and-safety-risk-parameters]. The Clearinghouse pauses risk-increasing trades that further enlarge oracle-mark divergence; closing or reducing a position that further breaches divergence is also disallowed unless divergence has already been breached[^drift-docs-2026-04-28-protocol-risk-and-safety-risk-parameters]. Maker post-only ask is auto-cancelled if the oracle's price is 2.5% above the maker's ask limit price; symmetric for bid 2.5% below[^drift-docs-2026-04-28-protocol-risk-and-safety-risk-parameters]. Taker orders that would push free collateral negative are also cancelled, and fillers receive a small reward for the cancellation[^drift-docs-2026-04-28-protocol-risk-and-safety-risk-parameters]. Each user sub-account can have up to 32 outstanding orders; market orders default to a 30s active time limit and a 2% max price-impact (`max_slippage_ratio`); within a single transaction, AMM fills are bounded by `max_base_asset_amount` per market[^drift-docs-2026-04-28-protocol-risk-and-safety-risk-parameters].

**Funding (capped symmetric, hourly).** Drift Funding Rate (per hour) = `1/24 * (market_twap − oracle_twap) / oracle_twap`[^drift-docs-2026-04-28-protocol-trading-perpetuals-funding-rates]. Mark TWAP = (bid_twap + ask_twap) / 2; TWAPs are EMAs with span = 1 hour[^drift-docs-2026-04-28-protocol-trading-perpetuals-funding-rates]. Settlement frequency is at end of hour. Hourly magnitudes are clamped by Contract Tier — B+: 0.125%; C: 0.208%; below C: 0.4167%[^drift-docs-2026-04-28-protocol-trading-perpetuals-funding-rates]. If no market trades or funding update calls occur within the first ~20 minutes of the hour, the next funding update is delayed by an additional hour[^drift-docs-2026-04-28-protocol-trading-perpetuals-funding-rates]. Funding rates are updated lazily on user actions (open/close/deposit), and cumulative funding rate accrues to position even between actions and shows as Unrealized P&L[^drift-docs-2026-04-28-protocol-trading-perpetuals-funding-rates]. Drift uses **Capped Symmetric Funding**: when long-short imbalance exists, a per-market **Rebate Pool** covers the cost delta — but capped at 2/3 of the Rebate Pool's available balance per interval, to prevent the Insurance Fund being drained by funding[^drift-docs-2026-04-28-protocol-trading-perpetuals-funding-rates]. Funding payments may not pay out for markets that trade infrequently[^drift-docs-2026-04-28-protocol-trading-perpetuals-funding-rates].

**Fees: 30-day volume tier × DRIFT-staking tier.** Drift's perp fee schedule is two-dimensional[^drift-docs-2026-04-28-protocol-trading-trading-fees]. Volume tier is on-chain 30-Day Volume; six tiers from Tier 1 (Rookie, ≤$2M) through VIP (>$200M) with taker rates 0.0350% / 0.0300% / 0.0275% / 0.0250% / 0.0225% / 0.0200% and a flat −0.0025% maker rebate at every tier[^drift-docs-2026-04-28-protocol-trading-trading-fees]. DRIFT staking tiers: Rookie (0 staked) 0% / 0%; Kickstarter (1k) −5% taker / +5% maker; Racer (10k) −10% / +10%; Elite (50k) −20% / +20%; Master (100k) −30% / +30%; Champion (250k) −40% / +40%[^drift-docs-2026-04-28-protocol-trading-trading-fees]. Staking benefits stack on top of the volume tier and apply to perp fees only[^drift-docs-2026-04-28-protocol-trading-trading-fees]. Worked examples: a Tier 3 taker (0.0275%) with 20% staking discount pays 0.022% effective; a maker (-0.0025% rebate) with 20% staking gets a -0.003% rebate[^drift-docs-2026-04-28-protocol-trading-trading-fees]. **High Leverage Mode** doubles the bottom-tier taker fee (a 2× penalty for the lowest-IM mode)[^drift-docs-2026-04-28-protocol-trading-trading-fees]. Maker rebate carve-outs: for non-BTC/ETH perpetuals, the flat maker rebate is −0.25 bps regardless of taker counterparty (AMM or User), and an order requires the `post only` flag to qualify as maker[^drift-docs-2026-04-28-protocol-market-makers-maker-fee-rebate]. DRIFT staking can add up to 40% extra rebate on top of this base[^drift-docs-2026-04-28-protocol-market-makers-maker-fee-rebate]. **Fee-Adjusted Markets** allow per-market increases (longer-tail assets) or flat discounts across all tiers[^drift-docs-2026-04-28-protocol-trading-trading-fees]. Drift reserves the right to end the promotional period and the Taker Incentive Program at any time without notice[^drift-docs-2026-04-28-protocol-trading-trading-fees]. Filler rewards are variable, up to 10% of the effective taker fee paid by the user[^drift-docs-2026-04-28-protocol-trading-trading-fees]. Spot fee values were a "Loading…" placeholder at crawl time and are NOT extracted in this snapshot[^drift-docs-2026-04-28-protocol-trading-trading-fees].

**Referral and builder codes.** Referrers earn 35% of the trading fees from users they refer (no max cap on receivable rewards); referred users receive a 5% discount[^drift-docs-2026-04-28-protocol-rewards-referral-links]. Rewards accrue ONLY from taker volume[^drift-docs-2026-04-28-protocol-rewards-referral-links]. Built-in sunset: referred users that reach Tier 3 and above (>$10M monthly volume) generate no referrer rewards or referee discount — explicit cap on the referral economics for high-volume traders[^drift-docs-2026-04-28-protocol-rewards-referral-links]. Attribution: a referral applies only to new Drift accounts created through the link, and the user must click, connect a wallet, and deposit within the same session (one-session attribution)[^drift-docs-2026-04-28-protocol-rewards-referral-links]. Referral links are user-customizable up to 32 characters and cannot be changed after first creation[^drift-docs-2026-04-28-protocol-rewards-referral-links]. **Drift Builder Codes (DBC)** are a separate integrator revenue-share, layered on top of SWIFT orders ONLY (not standard onchain orders)[^drift-developers-docs-2026-04-28-developers-drift-sdk-builder-codes]. Workflow: builder calls `initializeRevenueShare` (one-time); user creates a `RevenueShareEscrow` account (recommend `numOrders ≥ 8`); user calls `changeApprovedBuilder(builderAuthority, maxFeeTenthBps, true)` to approve a builder with a max-fee cap (in tenths of a basis point: 100 = 10 bps, 200 = 20 bps); per-SWIFT-order, the builder's app injects `builderIdx` and `builderFeeTenthBps` into the signed message; fees auto-settle to the builder's revenue-share account on fill[^drift-developers-docs-2026-04-28-developers-drift-sdk-builder-codes].

**Liquidations: partial, slot-paced, oracle-anchored.** Drift uses partial liquidation with a slot-based pacing window (default 25 slots): if price keeps moving against the user, liquidation accelerates; if price improves, it decelerates[^drift-docs-2026-04-28-protocol-trading-liquidations-liquidation-engine]. The buffer leaves liquidated accounts slightly behind a safe margin buffer rather than right at maintenance margin — reduces immediate re-liquidation risk[^drift-docs-2026-04-28-protocol-trading-liquidations-liquidation-engine]. Liquidations reference the **oracle price**, NOT mark price[^drift-docs-2026-04-28-protocol-trading-liquidations-liquidation-engine]. The engine compares current oracle to the 5-minute oracle TWAP — if deviation is ≥50%, liquidations are temporarily blocked to wait for additional oracle confirmation[^drift-docs-2026-04-28-protocol-trading-liquidations-liquidation-engine]. PositionFlag enum: IsolatedPosition = 1, BeingLiquidated = 2, Bankruptcy = 4[^drift-sdk-docs-2026-04-28-concepts-positions].

**Insurance Fund hierarchy and bankruptcy waterfall.** Drift's Insurance Fund is the first solvency backstop, and is multi-asset: separate pools for USDC, BTC, ETH, and SOL — each pool only covering same-denomination liabilities[^drift-docs-2026-04-28-protocol-insurance-fund]. The USDC pool collects exchange fees from spot+perp trading and supports liquidations from perp trading; SOL/BTC/ETH pools backstop borrow-lend losses for those assets[^drift-docs-2026-04-28-protocol-insurance-fund]. Funded jointly by stakers (anyone can stake the corresponding asset) and protocol via premiums collected from liquidation, trading, and borrow fees[^drift-docs-2026-04-28-protocol-insurance-fund][^drift-docs-2026-04-28-protocol-trading-liquidations-liquidation-engine]. Coverage scope: spot markets covered in full; perpetual markets covered up to a per-market limit[^drift-docs-2026-04-28-protocol-trading-liquidations-liquidation-engine][^drift-docs-2026-04-28-protocol-insurance-fund]. **Perp bankruptcy waterfall**: external Insurance Fund (USDC) covers debt up to per-market limit → vAMM lifetime profit (internal insurance) covers remainder → socialized loss applies pro rata across all open positions in that market[^drift-docs-2026-04-28-protocol-trading-liquidations-liquidation-engine]. Socialized loss splits: perp traders pay pro-rata by base amount across open positions; lenders pay pro-rata by token amount[^drift-docs-2026-04-28-protocol-insurance-fund]. **Isolated Insurance Funds** are assigned to highly volatile markets, separate from the standard fund and funded EXCLUSIVELY by premiums collected for that market — users in an isolated-IF market do not have access to the standard IF for losses beyond the limited fund[^drift-docs-2026-04-28-protocol-insurance-fund].

**Insurance Fund Staking.** IF stakers earn a proportionate share of the Revenue Pool every hour: `Staker share = Total Staked Amount / Total Insurance Fund`[^drift-docs-2026-04-28-protocol-insurance-fund-staking]. Revenue Pool is funded by borrow fees, spot exchange fees, perp exchange fees, and liquidation fees[^drift-docs-2026-04-28-protocol-insurance-fund-staking]. Each hourly settlement is split between IF Stakers and a protocol-owned IF portion[^drift-docs-2026-04-28-protocol-insurance-fund-staking]. **13-day cooldown** for unstaking; staked amount earns no rewards during cooldown[^drift-docs-2026-04-28-protocol-insurance-fund-staking]. Cannot unstake while spot market utilization (or 1hr utilization TWAP) is above 80%[^drift-docs-2026-04-28-protocol-insurance-fund-staking]. Only one pending unstake request per vault at a time; cancelling and resubmitting restarts the 13-day clock[^drift-docs-2026-04-28-protocol-insurance-fund-staking]. All earned rewards compound the staked amount[^drift-docs-2026-04-28-protocol-insurance-fund-staking].

**Drift Safety Module (DRIFT-staked backstop).** The Drift Safety Module (DSM) is a fully on-chain automated bad-debt cover system layered above the standard Insurance Fund[^drift-docs-2026-04-28-protocol-risk-and-safety-drift-safety-module]. Users stake DRIFT into a DSM insurance fund pool; if a deficit arises in a given asset, staked DRIFT is automatically used as backstop, removing the need for governance intervention or manual action[^drift-docs-2026-04-28-protocol-risk-and-safety-drift-safety-module]. Risk is **asset-isolated**: staking DRIFT covers bad debt in DRIFT pairs ONLY[^drift-docs-2026-04-28-protocol-risk-and-safety-drift-safety-module]. Slashing is the symmetric risk to receiving safety incentives. Safety incentive parameters are determined by successfully-passed DAO governance proposals; further DRIFT utility (validator and other network functions) can be added over time through the same channel[^drift-docs-2026-04-28-protocol-risk-and-safety-drift-safety-module]. Bankruptcy risk in DSM is compensated by the Revenue Pool, similar to other IF pools[^drift-docs-2026-04-28-protocol-risk-and-safety-drift-safety-module].

**LP surfaces (A5 is applicable).** Three LP surfaces exist on Drift, all distinct from a spot AMM: (1) **lpShares (vAMM LP)** — users can LP into the vAMM to provide additional collateral; the user's effective position is transferred to the AMM and the user earns a portion of trading fees and shares AMM PnL; cooldown ~24 hours after add before remove allowed[^drift-docs-2026-04-28-protocol-about-v3][^drift-sdk-docs-2026-04-28-concepts-positions]. (2) **Backstop AMM Liquidity (BAL)** — external passive LP layered onto the v3 vAMM curve as one of three runtime knobs[^drift-docs-2026-04-28-protocol-about-v3-drift-amm][^drift-docs-2026-04-28-protocol-about-v3]. (3) **Insurance Fund Staking** — depositor-style yield surface backed by Revenue Pool flows (see above)[^drift-docs-2026-04-28-protocol-insurance-fund-staking][^drift-docs-2026-04-28-protocol-insurance-fund]. The DSM is conceptually adjacent (token-staked backstop) but is a credit-staking + slashing primitive, not an LP primitive.

**Delisting (four-stage, on-chain).** Delisting follows an on-chain procedure analogous to derivatives expiry[^drift-docs-2026-04-28-protocol-risk-and-safety-delisting-process]. **Stage 1** — once an expiry date is set, the perp market enters reduce-only mode: all new orders forced to reduce-only; risk-increasing orders cancelled on fill; no funding updates; users cannot pre-settle unrealised P&L[^drift-docs-2026-04-28-protocol-risk-and-safety-delisting-process]. **Stage 2** — after expiry, anyone calls `settle_expired_market` to lock in a settlement price (target = AMM's calculated 5-min oracle TWAP, altered to allow full solvency)[^drift-docs-2026-04-28-protocol-risk-and-safety-delisting-process]. **Stage 3** — after expiry + optional settlement-duration buffer, users settle expired positions at the settlement price; insurance fund draws and/or socialized loss may occur; taker fee applied at closure (encouraging early reduce-only close)[^drift-docs-2026-04-28-protocol-risk-and-safety-delisting-process]. **Stage 4** — once user count hits zero, remaining PnL Pool balance settles into the quote asset's Revenue Pool[^drift-docs-2026-04-28-protocol-risk-and-safety-delisting-process]. Spot delisting: reduce-only mode blocks new borrows/deposits/buys; spot force-close mode is documented as "coming soon"[^drift-docs-2026-04-28-protocol-risk-and-safety-delisting-process].

**Prelaunch markets.** Prelaunch markets allow users to trade an asset before a reliable external oracle exists[^drift-docs-2026-04-28-protocol-trading-prelaunch-markets]. They use a custom oracle source set to the current mark TWAP (window = funding period); each Prelaunch oracle has both an initial price and a max price (oracle value cannot exceed max)[^drift-docs-2026-04-28-protocol-trading-prelaunch-markets][^drift-docs-2026-04-28-protocol-trading-market-specs]. Default contract tier is **Highly Speculative** — no access to external insurance fund (insurance is fees collected within the market only)[^drift-docs-2026-04-28-protocol-trading-prelaunch-markets]. Configured with custom max-price and conservative open-interest limits to resist manipulation[^drift-docs-2026-04-28-protocol-trading-prelaunch-markets]. Once a reliable external oracle is available, the oracle source can be switched[^drift-docs-2026-04-28-protocol-trading-prelaunch-markets].

**Audits and bug bounty.** First-party audits page lists three audits: **Trail of Bits** (Nov 7 – Dec 2, 2022, with Jan 23–25, 2023 fixup review; no high-severity findings; the undetermined finding "test code in production" is documented on page 77 of the report); **Neodyme** (May 10, 2024, last updated June 27, 2024; scope: protocol-v2); **OtterSec** (Metamask Snap "Connect" by Drift)[^drift-docs-2026-04-28-protocol-risk-and-safety-audits]. Trail of Bits is described as a Tier-1 security auditor[^drift-docs-2026-04-28-protocol-risk-and-safety-audits]. Bug bounty program (severity classified per Immunefi rules): **Critical** (funds drainage / theft without signatures) up to **$500,000**; **High** (funds freezing or incorrect value assignment) **$10,000–$50,000**; **Medium/Low** (other bugs not threatening funds) **$1,000–$5,000**[^drift-sdk-docs-2026-04-28-program-security]. Submission: hello@drift.trade; required: detailed attack vector, proof-of-concept (for critical/high), reproduction steps; response within 1 business day; paid in USDC[^drift-sdk-docs-2026-04-28-program-security]. Out of scope: already-exploited attacks, leaked credentials, privileged address access, oracle data issues (except manipulation), liquidity issues, third-party bot errors, social engineering, DoS, Immunefi rules violations[^drift-sdk-docs-2026-04-28-program-security]. Public disclosure before reporting is forbidden[^drift-sdk-docs-2026-04-28-program-security]. Documented security best-practices: oracle guard rails (staleness, confidence interval, mark/oracle divergence, TWAP), size-based margin scaling, per-market position limits, progressive liquidation[^drift-sdk-docs-2026-04-28-program-security].
